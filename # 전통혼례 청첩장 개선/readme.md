# 엄지 · 이도연 모바일 청첩장

메인 파일은 **`index.html`**입니다. 바닐라 HTML/CSS/JavaScript로 실행되며 빌드가 필요 없습니다.

이 폴더 전체를 압축해서 전달하세요. `assets/`, `photos/`, `patterns/`는 화면에 필요한 파일, `scripts/`는 Apps Script와 점검·설정 도구, `readme.md`와 `AGENTS.md`는 인수인계 안내입니다. 이전 DC 파일, 사용하지 않는 시안 이미지·문양, support.js 및 전달용 ZIP은 제거했습니다.

## 반영한 사항

- 원본의 녹색·크림색, 전통 문양, 초대글, 가족 소개, 예식 순서와 메인 사진 A를 유지했습니다. DC 편집 화면의 휴대폰 프레임과 사진 A/B 비교 버튼은 제외했습니다.
- 상단 `가 / 가 / 가`는 각각 기본, 125%, 150% 크기를 선택합니다. 반복해서 눌러도 해당 크기로 유지되며, 가장 작은 버튼으로 원래 크기로 돌아갑니다. 선택한 크기와 언어만 브라우저에 저장합니다.
- 한국어·영어 전환을 구현했습니다. **축가 제목·가사·크레딧은 원본 한국어 그대로 유지**합니다. 인명 영문 표기는 임시 로마자 표기이므로 본인이 사용하는 표기로 확인해 주세요.
- 첨부 교통 안내에 따라 주소, 예절원 전화번호, 낙성대역 4번 출구 → 관악02번 → 관악영어마을 하차 → 횡단보도 건너기 안내를 반영했습니다. 약도 자리에는 읽기·번역·확대가 가능한 단계별 이동 안내를 넣었습니다. Google 지도를 본문 폭에 맞춰 삽입했습니다. 별도 지도 서비스 버튼은 제거했습니다. 영어 모드에서는 지도 제목과 Google 지도 언어 설정도 영어로 전환합니다.
- 하단 고정 RSVP 버튼 → 같은 화면의 모달. 성함과 신랑측/신부측만 필수이며, 비건식·1부·2부·3부는 각각 독립된 체크박스, 연락처는 선택입니다. 전부 불참이면 세 참석 체크박스를 비워 보낼 수 있습니다.
- 공유 제목·설명·1200×630 썸네일을 준비했습니다. 공유 버튼은 휴대폰 기본 공유 메뉴를 사용하고, 지원되지 않으면 링크를 복사합니다. 카카오 전용 SDK/키는 사용하지 않았습니다.

## 아직 설정해야 하는 것

**제공받은 Apps Script 웹 앱 주소를 CONFIG.rsvpEndpoint에 반영했습니다.** 실제 응답 제출 및 시트 기록은 아직 확인하지 않았습니다. 청첩장 공개 배포 주소와 메신저 미리보기 설정도 필요합니다. 아래 시트 연결 절차는 새로 설정하거나 이관할 때 참고하세요.

| 항목 | 수정 위치 |
| --- | --- |
| RSVP 웹 앱 주소 | `assets/invitation.js` 맨 위 `CONFIG.rsvpEndpoint` |
| 저장할 시트 ID | `scripts/Code.gs` 맨 위 `SETTINGS.spreadsheetId` |
| 실제 배포 주소 / 공유 이미지 절대 주소 | 아래 공유 설정 절차 |
| 문자통역·온라인 중계 링크 | `CONFIG.captions`, `CONFIG.livestream` |
| 계좌 | `CONFIG.groomAccounts`, `CONFIG.brideAccounts` |
| 갤러리 사진, 비건 메뉴, 이동 지원 확정 정보 | HTML 해당 섹션 + JS의 `EN` 번역표 |
| 인명 영어 표기, 3부 장소·시간, 행사 안내 정확성 | HTML 원문 및 `EN` 번역표 |

원본의 가짜 계좌번호, 무료 주차 시간, 미확인 엘리베이터·화장실 위치는 실제 정보처럼 노출하지 않도록 준비 중/문의 안내로 바꿨습니다. 갤러리는 원본에 실제 사진이 없어서 준비 중 상태입니다. 행사 측이 확정한 내용을 넣어 주세요.

## Google 스프레드시트 연결하기

1. 본인 Google 계정에서 **새 Google 스프레드시트**를 만듭니다. 제목 예: `엄지 이도연 결혼식 RSVP`. 응답 시트 자체는 공개할 필요가 없습니다.
2. 시트 주소 `https://docs.google.com/spreadsheets/d/여기가_시트_ID/edit`에서 ID 부분만 복사합니다.
3. 스프레드시트에서 **확장 프로그램 → Apps Script**를 엽니다.
4. 기본 코드를 지우고 전달받은 `scripts/Code.gs` 내용을 붙여 넣습니다. `SETTINGS.spreadsheetId`를 저장할 시트 ID로 설정합니다. 현재 로컬 코드에는 `2026_엄지 결혼식 하객 리스트` 시트 ID가 입력되어 있습니다. 다른 시트로 이관할 때만 교체하세요.
5. 저장하고 상단 함수 선택에서 `setup`을 골라 한 번 실행합니다. 본인의 시트에 쓰기 위한 Google 권한을 승인합니다. 새 `RSVP` 탭과 제목 행이 생기는지 확인합니다.
6. **배포 → 새 배포 → 웹 앱**을 선택합니다. 실행 사용자: **나**, 액세스 사용자: **모든 사용자**로 설정해 배포합니다. 조직 계정에서 이 선택이 제한되면 계정 관리자에게 확인해야 합니다. 이 방식은 하객이 로그인하지 않고 응답하도록 스크립트 소유자의 권한으로 실행합니다. [Google 공식 웹 앱 안내](https://developers.google.com/apps-script/guides/web)
7. 끝이 `/exec`인 웹 앱 URL을 복사합니다. `/dev` 주소나 스프레드시트 주소를 넣으면 안 됩니다.
8. `assets/invitation.js`의 설정을 수정합니다.

```js
const CONFIG = {
  rsvpEndpoint: "https://script.google.com/macros/s/발급받은_배포_ID/exec",
  captions: "",
  livestream: "",
  groomAccounts: [],
  brideAccounts: []
};
```

9. 실제 배포한 청첩장을 열어 테스트 이름으로 제출합니다. **화면의 성공 안내와 시트의 새 행을 둘 다 확인**합니다. 이름·신부측 선택만 하고 연락처/참석 체크를 모두 비워도 접수되는지, 비건식과 1·2·3부가 각각 맞게 기록되는지도 확인합니다.
10. `Code.gs`를 고치면 **배포 → 배포 관리 → 수정 → 새 버전**으로 기존 배포를 업데이트합니다. 새 배포를 만들면 URL도 다시 바꿔야 합니다.

시트 열은 `번호 / 접수 날짜 (한국시간) / 성함 / 신랑측·신부측 / 비건식 필요 / 1부 참석 / 2부 참석 / 3부 참석 / 연락처 / 요청 ID` 순서입니다. 체크 값은 `TRUE/FALSE`로 저장되므로 필터로 필요한 인원을 셀 수 있습니다. 이름과 연락처는 텍스트로 다루며, 연락처 앞자리 0을 유지합니다.

번호와 날짜는 서버가 넣습니다. 동시 제출은 잠금으로 직렬화하고, 같은 전송을 재시도하면 요청 ID로 중복 행 생성을 막습니다. 전송이 실패하면 입력을 유지합니다. 요청 ID는 화면에 보이지 않는 마지막 열로 저장됩니다. 접수 후 다른 내용을 다시 보내면 새 번호의 행이 추가되므로 수정 응답은 담당자가 최신 내용을 확인해 주세요. 번호를 재사용하지 않으려면 접수 행을 삭제하지 말고 따로 표시하세요.

프런트는 JSON 본문을 `text/plain` POST로 전송하며, 서버가 반환하는 JSON의 `ok`, `number`, `requestId`를 확인해야 성공으로 처리합니다. `no-cors`로 바꾸거나 오류를 무시해 성공으로 처리하면 실제 저장을 확인할 수 없으므로 그렇게 수정하지 마세요. Apps Script Content Service는 다른 Google 주소로 응답을 리다이렉트하므로 이를 허용해야 합니다. [Google Content Service 안내](https://developers.google.com/apps-script/guides/content)

문제 해결: 미설정 안내 → CONFIG 확인. 접수 실패 → `/exec` 주소·배포 접근 권한·시트 ID·스크립트 실행 기록 확인. 제목 행의 열 순서를 바꾸면 코드의 열 구조와 달라져 저장이 중단됩니다. 테스트 모의 검증은 완료했지만 Google 실서비스 연결 검증은 위 설정 후 필요합니다.

## 로컬에서 보기 / 배포하기

HTML을 더블클릭하면 화면과 기본 상호작용을 볼 수 있습니다. 공유·클립보드·RSVP 네트워크 기능의 최종 확인은 HTTPS 사이트에서 진행하세요. Python이 설치되어 있으면 폴더에서 다음처럼 미리 볼 수도 있습니다.

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 열면 `index.html`이 바로 열립니다.

정적 웹 호스팅에는 `index.html`, `assets/`, `photos/`, `patterns/`를 올립니다. `scripts/`, `readme.md`, `AGENTS.md`는 관리·인수인계용이므로 공개 서버에는 없어도 됩니다. `/id30-vanilla`의 홈커밍 RSVP 주소나 Kakao 키는 이 프로젝트로 복사하지 않았습니다.

## Open Graph 공유 설정

- 썸네일: `assets/og-wedding.jpg` (1200×630).
- 편집 가능한 카드 원본: `assets/og-card.html`. 기존 문양과 글자로 구성한 카드입니다. 이름·날짜를 변경하면 이 원본도 고치고, 1200×630 크기로 렌더링한 JPEG를 다시 저장하세요. HTML만 변경해도 JPG가 자동 변경되지는 않습니다.
- 제목·설명은 HTML `<head>`의 `title`, `description`, `og:title`, `og:description`, `twitter:title`, `twitter:description`에 있습니다.
- 실제 URL을 아직 몰라 이미지 주소는 상대 경로로 두었습니다. 공개 주소가 확정되면 아래 명령을 실행해 **HTML 소스 안에** `og:url`, `canonical`, `og:image`, `twitter:image` 절대 주소를 넣으세요. JavaScript로만 삽입하면 일부 메신저가 읽지 못합니다.

```sh
python3 scripts/set-site-url.py https://본인의-실제-도메인/
```

하위 경로에서 서비스한다면 `https://도메인/wedding/`처럼 마지막 `/`까지 넣습니다. 명령을 실행한 뒤 HTML을 다시 업로드하고, 페이지 소스에서 실제 도메인이 들어갔는지 확인합니다. 이미지 URL을 직접 열어 보세요. 링크를 메신저에 붙여 넣어 제목·사진을 확인하고, 예전 이미지가 남으면 해당 서비스의 공유 캐시를 갱신하세요.

## 계좌 추가 예시

`assets/invitation.js`의 `CONFIG` 배열에 **확인한 실제 계좌**만 넣습니다.

```js
groomAccounts: [
  { name: "신랑 엄지", nameEn: "Groom Eom Ji",
    bank: "은행명", bankEn: "Bank name", number: "실제 계좌번호" }
],
brideAccounts: []
```

빈 배열이면 준비 중 안내가 보입니다. 복사 버튼은 계좌번호만 복사합니다.

## GPT로 수정 부탁하기

일반 채팅에서는 필요한 파일을 함께 첨부하고, 폴더를 읽는 도구에서는 압축을 푼 프로젝트 폴더를 열어 주세요. 화면을 설명할 때는 현재 화면 캡처도 도움이 됩니다. 아래 문장을 복사해 요청할 수 있습니다.

> 이 폴더는 엄지·이도연 모바일 청첩장입니다. readme.md와 AGENTS.md를 먼저 읽어 주세요. HTML은 index.html이며 assets/invitation.css, assets/invitation.js를 함께 사용합니다. 바닐라 HTML/CSS/JS 구조를 유지하고 DC·React·npm·빌드 도구는 추가하지 마세요. 기존 색상, 사진, 문양과 지정하지 않은 내용은 유지해 주세요. 한국어 문구를 바꾸면 EN 번역표도 함께 업데이트하되 축가 가사 원문은 유지하세요. 수정할 내용: [원하는 변경을 구체적으로 적기]. 실제 파일을 수정하고 무엇을 바꿨는지 알려 주세요. 시트 전송 성공 확인과 필수값 검증이 계속 작동하는지 점검해 주세요.

예: “2부를 18:10–19:10으로 바꾸고 영문도 고쳐줘”, “비건 메뉴를 아래 세 가지로 바꿔줘”, “첨부한 사진 세 장을 함께한 날들에 넣고 크게 보기 기능을 추가해줘”.

날짜·이름을 변경하면 본문, 영어 번역, 페이지 메타태그, 공유 카드 원본과 JPG까지 함께 수정해야 합니다. HTML 문장의 정확한 한국어 문자열을 `EN` 사전의 키로 사용하므로 원문만 바꾸면 그 문장은 영어 전환 대상에서 빠집니다.

## RSVP 오류 점검 (2026-09-12)

앞선 점검에서는 설정된 `/exec` 주소에 로그인 없는 GET 요청 시 HTTP 403과 “액세스 권한 필요”가 반환되었습니다. 하객의 익명 요청이 허용되도록 Apps Script의 **배포 → 배포 관리 → 해당 웹 앱 선택 → 수정**에서 **실행 사용자: 나 / 액세스 권한: 모든 사용자**를 확인하고 배포하세요. Google 계정이 있는 사용자만 허용하는 선택은 익명 접근과 다릅니다. 조직 정책으로 모든 사용자를 선택할 수 없다면 해당 정책 확인이 필요합니다.

설정 후 로그아웃한 브라우저/시크릿 창에서 `/exec`를 열어 `{"ok":true,"service":"wedding-rsvp"}`가 보이는지 확인하세요. 이 GET 확인은 제출 행을 만들지 않습니다. 그다음 청첩장에서 테스트 응답을 제출하고 시트의 새 행을 확인하세요. 새 배포를 만들어 URL이 바뀌었다면 `CONFIG.rsvpEndpoint`도 갱신해야 합니다. 스프레드시트 자체를 공개할 필요는 없습니다.

### 실행 로그로 확인한 추가 원인

첨부된 `setup` 실행 로그는 `Illegal spreadsheet id or key: PASTE_SPREADSHEET_ID_HERE`입니다. 클라우드 Apps Script의 시트 ID가 임시값으로 남아 있습니다. 로컬 `scripts/Code.gs`에는 실제 하객 명단 시트 ID를 반영했으므로 이 코드를 Apps Script에 다시 붙여 넣고 저장 → `setup` 실행 → RSVP 탭 생성 확인 → 웹 앱 새 버전 배포 순으로 진행하세요. 로컬 수정이 Google 편집기에 자동 동기화되지는 않습니다.

`https://script.google.com/macros/library/d/.../1`은 라이브러리 주소이며 RSVP 전송용이 아닙니다. 배포 유형을 **웹 앱**으로 선택하고 `https://script.google.com/macros/s/.../exec` 형식의 웹 앱 URL을 복사해야 합니다. 클라이언트의 기존 URL은 새 웹 앱 URL이 확인될 때까지 유지했습니다.

### 새 웹 앱 배포 확인

새로 전달받은 `/exec` 주소를 `assets/invitation.js`의 `CONFIG.rsvpEndpoint`에 반영했습니다. 로그인 없는 GET 요청에서 `{"ok":true,"service":"wedding-rsvp"}` 응답을 확인했습니다. 이전 403 접근 오류는 새 주소에서 재현되지 않았습니다. 실제 POST 제출과 시트 행 추가는 별도 테스트가 필요합니다.
